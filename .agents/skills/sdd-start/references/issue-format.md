# issue.md の書き方

`issue.md` は、issueトラッカーから取り込んだ内容を正規化したスナップショットである。
以降の工程（要件・設計・タスク）は元のissueを見に行かず、このファイルだけを入力にする。
後からトラッカーとの自動連携を足すときも、このファイルを作る処理を足すだけで済むよう、形式をそろえる。

## 形式

`assets/issue-template.md` の見出しと項目をそのまま使う。見出しの名前や順序は変えない。

| 部分 | 書き方 |
|---|---|
| タイトル（`# ` の行） | `<ID> <issueのタイトル>`。HTMLのページタイトルにもなる |
| 出典 | 手動で取り込んだ場合は `manual` |
| 取り込み日時 | ISO 8601 形式（例: `2026-09-30T10:00:00+09:00`） |
| モード | sdd-start で決めたモード（`完全モード` か `軽量モード`）。モードを切り替えたら更新する |
| 背景・目的 | 本文から、なぜ必要か・何を実現したいかを整理して書く |
| 受け入れ条件 | issueに書かれているものだけを箇条書きにする。無ければ「未記載」 |
| コメント | 仕様に関わる議論の要点。決まったこと、却下されたこと、未決のことが分かるように書く |
| 添付ファイル | `attachments/` に置いたファイルごとに、何が写っているか・何が書かれているかを1行で書く |
| 原文 | 受け取った本文とコメントを、4つのバッククォートで囲んでそのまま残す |

## 守ること

- **書かれていないことを書き足さない。** 整理はしても、解釈や補完はしない。
  足りない情報は、要件を作るとき（sdd-req、sdd-quick）にユーザーへ質問する。
- 原文は要約しない。後で「元のissueに何と書いてあったか」を確かめるために残す。
- 個人の連絡先、パスワード、APIキーなどの秘密情報が含まれていたら、ユーザーに伝え、伏せ字にしてよいかを確認する。
- 画像の添付は、AIが中身を読み、何が写っているかを「添付ファイル」に書く。
