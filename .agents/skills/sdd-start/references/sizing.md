# 規模の判定基準（完全モードか軽量モードか）

AIが判定して提案し、担当者が決める。

軽量モードは、主に完全モードで作った機能の後の修正（バグの修正、小さな仕様変更）に使う。

## 判定基準

| 判定の観点 | 軽量モード | 完全モード |
|---|---|---|
| 種類 | バグの修正、小さな仕様変更 | 新機能、仕様の大きな変更 |
| 影響範囲 | 1つのモジュールの中に収まる | 複数のモジュールにまたがる |
| 公開API、DBのスキーマ | 変更しない | 変更する |
| 依存ライブラリ | 追加しない | 追加する |
| タスク数の目安 | 3件以下 | それ以上 |

- 1つでも完全モードに当てはまる観点があれば、完全モードを提案する。
- 判断がつかない観点があれば、そのことを明示する。分からないまま軽量モードを提案しない。

## 調べ方

issueの内容だけでは影響範囲が分からないことが多い。次を短時間で調べる。

1. `docs/sdd/architecture.ts` の `modules` から、関係しそうなモジュールを挙げる。
2. issueに出てくる画面名、API名、用語で、コードを検索する。
3. 見つかったファイルが、どのモジュールに属するか、公開APIやDBのスキーマに関わるかを確かめる。

ここでは設計はしない。判定に必要なことだけを調べる。

## 伝え方

次の形でユーザーに示す。

```
判定: 軽量モードを提案します

| 観点 | 判定 | 理由 |
|---|---|---|
| 種類 | 軽量 | 件数表示の不具合の修正 |
| 影響範囲 | 軽量 | src/search/pagination.py だけ（search モジュール） |
| 公開API、DBのスキーマ | 軽量 | 変更なし |
| 依存ライブラリ | 軽量 | 追加なし |
| タスク数の目安 | 軽量 | 再現テストと修正の2件 |

触りそうなファイル: src/search/pagination.py
```

## モードの切り替え

- 軽量モードの途中で、公開APIやDBの変更が必要だと分かったら、完全モードへ切り替える。
  `spec.ts` は、sdd-req で要件を作るときの入力として引き継ぐ。
- 切り替えたら、`issue.md` の「モード」を更新する。
