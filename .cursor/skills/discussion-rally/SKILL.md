# discussion-rally

A、B、C、D の4人で、A → B → C → D の順に5回書く。AとBの主張は、このスキルには書かない。呼び出しのときにユーザーが渡した文を使う。

スキルを呼び出したこと（`/discussion-rally`）は、確認ポイントへの回答ではない。

## 確認ポイント

ユーザーの回答を待つのは次だけである。それ以外は止まらずに進める。質問は1件ずつにする。

1. Aの主張が無い。どの案に賛成するのかを聞く。
2. Bの主張が無い。何に反対するのかを聞く。
3. 書き先がすでに別の議論の本文を持っている。上書きするか、別のパスへ書くかを聞く。

書き先の指定が無いときは、ワークスペース直下の `ディスカッション.md` にする。

## サブエージェント

4人とも Task ツールで起動する。`subagent_type` は `generalPurpose`、`model` は `grok-4.7-medium` にする。同じ回の中では、前の人が書き終わるまで次を起動しない。2回目以降は、同じ4人を `resume` で続ける。

各人への指示には、その回までに必要なものだけを書く。Cへは、下の「Cの手順」以外の例や候補を足さない。

共通の指示は次のとおりである。

- 先に書き先を全文読む。
- 日本語の常体で、末尾に追記する。既存の本文は消さない。
- 見出しは `## 第N回 — 名前` だけにする。名前は `A`、`B`、`C（代替案）`、`D（折衷案）` である。
- 根拠にした記事や一次情報があれば、URL とともに書く。確認できなかった URL は書かない。
- 書き先以外のファイルは変えない。コミットしない。
- 親への返信は、追記した見出しの要約と、引いた URL の一覧だけにする。

初回の前に、書き先が無いか空なら、見出しと参加者だけを置く。AとBの欄には、ユーザーが渡した主張をそのまま書く。

```markdown
# ディスカッション

- **A**: （ユーザーが渡した主張）
- **B**: （ユーザーが渡した主張）
- **C**: 代替案
- **D**: 折衷案

各回は A → B → C → D の順。書いた人は、それまでにこのファイルへ書かれた意見を読んでから書く。根拠にした記事や一次情報は URL とともに残す。

---
```

## 各人の役割

Aには、ユーザーが渡したAの主張をそのまま役割として渡す。その主張から外れない。

Bには、ユーザーが渡したBの主張をそのまま役割として渡す。その主張から外れない。

Cの手順は、次の文だけを渡す。

```
Cは、AとBを読んでから代替案を作ってください。案の中身はあらかじめ決めないでください。この欄に書いていない例や候補は足さないでください。
Bの反対を一つずつ取り上げ、その反対を外したときに、結果が変わるかを書いてください。
結果が変わる反対だけを、案が満たすべき条件にしてください。
結果が変わらない反対では、Aの案を却下しないでください。
Aの案を変えてよいのは、結果が変わる反対を、その案では満たせないと書いたときだけです。
結果が変わらないと言うときは、その手段を書いてください。
手段には、今検討している変更、スキルの文章、人の確認を含めてよいです。
```

2回目以降のCには、同じ手順で、それまでに増えた反対を反映するよう付け加える。

Dには、折衷案を書くことと、Cの案の再掲にはしないことだけを渡す。

## 結論

5回がすべて書き終わってから、親が書き先を読んで、理由を含めた結論をユーザーに返す。結論はファイルへ追記しない。
