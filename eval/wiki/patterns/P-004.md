# P-004 drift が、SDD の導入で増えた docs/ を構成の変更として報告する

- 状態: 道具で検出（2026-10-10。QUICK-001 の再実行で確かめる）
- 起きた工程: sdd-start の手順（`deno task drift` と確認ポイント2）
- 根拠: 20261010-140124-QUICK-001、20261010-142035-QUICK-001、20261010-143747-QUICK-001（3/3 回。composer-2.5、スキル 772db1e）

## 何が起きたか

3回とも、drift が「最上位のディレクトリが増えた: docs/」と報告した。AI は architecture.ts に反映されていない構成の変更として、
確認ポイント2で「architecture.ts の更新をどうするか」を人に聞いた（人役の回答表では「今回は扱わない」）。

## なぜ起きたか

architecture.ts の basedOn は SDD の導入の前のコミットを指す。導入のコミットで docs/ が初めてできる。
drift は変わったファイルの一覧からは docs/sdd と docs/specs を除いていたが、最上位のディレクトリの比較では除いていなかった。

## なぜ問題か

導入した案件では、architecture.ts を更新するまで毎回、構成の変更ではないことを人に聞くことになる。
人の関わりを受け入れ条件と受け入れテストに絞る方針に反し、本当の構成の変更の報告も埋もれる。

## 対策

道具: 最上位のディレクトリの比較でも、docs/sdd と docs/specs の下のファイルだけでできたディレクトリを数えない。
docs/ に他のファイルが増えたときは、これまでどおり報告する（tests/tools_test.ts）。

## 試した対策（skill-impact.md の行）

- 2026-10-10: drift.ts を上のとおり直した。試験場の v0.1.1 で、構成の変更が見つからないと報告することを確かめた。
