# P-002 品質ゲートの整形と lint が、SDD のスキルと道具まで対象にする

- 状態: 道具で検出（2026-10-11 採用。自動実行で INIT-001 は 1/3 → 3/3、VAL-002 は合格 0 のまま）
- 起きた工程: sdd-init の「ツールの選定と品質ゲート」
- 根拠: 20261010-115030-INIT-001 ほか 3/3 回（採点で `gate --full` を流したとき）

## 何が起きたか

登録した `format`（`composer lint && npm run check:fix`）を導入直後の状態で実行すると、128 ファイルが書き換わった。
`.agents/skills/` と `docs/sdd/`（sdd-init が上書きで管理する道具）も含まれていた。
`vp check` は `docs/sdd/` の Deno のコード（`Deno.ChildProcess` など）にも警告を出している。

## なぜ問題か

- sdd-impl はタスクごとに `gate` を流すので、毎回スキルと道具が書き換わり、タスクのコミットに関係のない差分が混ざる。
- `docs/sdd/` の道具は sdd-init で上書きされるので、書き換えても次の更新で元に戻る（差分が行ったり来たりする）。

## その後の観察（3巡目、スキル cc870e8+変更(b4c5510)）

- 20261010-131812-INIT-001: `format` に `npm run check:fix` を登録した。sdd-impl の gate のたびに、スキル、道具、アプリのコードが整形される。
- 20261010-132655-INIT-001: 途中で `check:fix` を流し、アプリのコードは戻したが、整形された `docs/sdd/`（引用符が `'` になった道具と config.ts）をそのまま導入のコミットに入れた。
- AI 自身も「vp check が `.agents/` や `docs/sdd/` など130ファイルで整形の差分を検出する」と報告していた（20261010-131812-INIT-001）。

## 確認（2026-10-11、既存の INIT-001 の記録）

- Sail 経由でも起きる。20261010-132655-INIT-001 は `./vendor/bin/sail npm run check:fix` を実行し、導入した `docs/sdd/` の引用符が `"` から `'` に、字下げが 4 スペースに変わった。スキルの資材（`.agents/skills/sdd-init/assets/sdd/`）との差分である。
- 書き換えたのは Pint ではない。`composer lint` は `pint` で PHP だけを整形する。変わったのは `package.json` の `check:fix`（`vp check --fix`）を流したあとである。
- 20261010-131812-INIT-001 は format に `sail npm run check:fix` を登録したが、コミットされた `docs/sdd/` の引用符は資材のまま（`"`）だった。登録しただけでは起きず、実行したときに起きる。

## 試した対策（skill-impact.md の行）

- 2026-10-11 `gate` の実行後に、`.agents/` か `docs/sdd/` が実行前より変わっていたら失敗にする（終了コード 1）。自動実行で INIT-001 は 1/3 → 3/3、VAL-002 は合格 0 のまま。採用。

## 対策の案

- 道具: `doctor` で、整形・lint の設定が `.agents/` と `docs/sdd/` を除外しているかを確かめる（ツールごとに設定の形が違うので、まずは主要なものだけ）。
- 道具: `gate` の後に `.agents/` か `docs/sdd/` の道具が変わっていたら、警告を出す（ツールを問わず検出できる）。
- 手順: sdd-init で、品質ツールの除外の設定に `.agents/` と `docs/sdd/` を足すよう提案する。
