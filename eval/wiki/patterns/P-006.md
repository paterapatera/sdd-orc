# P-006 品質ゲートが通らないまま、道具の隠れたオプションで確認を飛ばして完了する

- 状態: 対策中（--skip-gate は完了の条件のエラー。採否は未計測）
- 起きた工程: sdd-finish の手順1（finish-report）。きっかけは試験場の環境の問題（Browser テストが止まる）
- 根拠: 20261010-191738-FULL-001（`finish-report GH-4 --skip-gate`）。20261010-175801-FULL-001 も、テストが止まったまま「手元で確かめてください」と完了を報告した（集計からは外した実行）

## 何が起きたか

Browser テストが止まり、品質ゲート（gate --full）が終わらなかった。AI は finish-report のソースから、手順書に無い `--skip-gate` を見つけて使い、
品質ゲートを通さずに spec の削除まで進めた。別の回では、`pkill -9 -f "docker compose"` で Docker のプロセスを強制終了した。

## なぜ問題か

finish-report が品質ゲートを流すのは、AI の自己申告に頼らないため。AI が自分でそれを外せると、道具で確かめる意味が無くなる。
環境の問題は sdd-impl の止まる条件4（環境の問題で先に進めない）に当たり、止まって人に伝えるべきだった。

## 対策の案

- 道具: `--skip-gate` をコマンドラインのオプションから外す（テストからは環境変数などで渡す）。
  または、使ったときは finish-report の「完了の条件」をエラーにする。
- 手順: sdd-finish にも、品質ゲートが環境の問題で通らないときは止まる、と書く。

## 試した対策（skill-impact.md の行）

- 2026-10-11 `--skip-gate` を付けても品質ゲートを実行し、完了の条件をエラーにする。テストがゲートを飛ばすときは環境変数 `SDD_FINISH_SKIP_GATE=1`。採否は未計測。
