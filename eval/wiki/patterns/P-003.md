# P-003 既存のコードが品質ゲートを通らないとき、導入のコミットでアプリのコードを直してしまう

- 状態: 道具で検出（2026-10-10 採用。試験場は v0.0.0 のまま、「既存のコードが通らない案件」として扱う）
- 起きた工程: sdd-init の手順6（コミット）。P-001 の対策（hook の品質ゲート）で表に出た
- 根拠: 20261010-122821-INIT-001、20261010-123622-INIT-001、20261010-124646-INIT-001（3/3 回。composer-2.5、スキル cc870e8+変更(65b5dea)）

## 何が起きたか

3回とも、登録したコマンドを Sail 経由に直し、品質ゲートを実際に流した（P-001 の対策は効いた）。
しかし基準のコードが品質ゲートを通らないため、`npm run check:fix`、`wayfinder:generate` などでアプリのコードと設定を書き換えて通し、
「SDDを導入」のコミットに混ぜた（`Modules/Demo/` の9ファイル、`resources/js/app.tsx`、`tsconfig.json`、`vite.config.ts`、`vite-module-loader.js`、`modules_statuses.json`）。
ユーザーには相談していない。

## 確かめた事実

試験場の `v0.0.0` は、それ自体が品質ゲートを通らない。

- `npm run check`（vp check）: 81 ファイルに整形の崩れ
- `npm run types:check`: Wayfinder の生成コード（`resources/js/actions/`、Git の対象外）で型エラー
- `composer check:php`、Pint: 通る

## なぜ問題か

- 導入（sdd-init）は恒久ドキュメントと道具を入れる作業で、アプリのコードを変える作業ではない。人のコードレビューが無いので、混ざった変更に誰も気づかない。
- hook が「通るまでコミットさせない」ので、通らない原因が既存のコードにあると、AI はコードを直す方向に押される（P-001 の対策の副作用）。

## 対策の案（試験場の扱いと合わせて決める）

- 手順: 品質ゲートが通らない原因が既存のコードにある場合は、sdd-init の中で直さない。失敗の内容と、直すための issue の案をユーザーに示して止まる（確認ポイント 6 を、コマンドの誤りと既存のコードの問題に分けて書く）。
- 道具: sdd-init の作業ブランチで、`docs/sdd/` と `.gitignore` 以外のファイルが変わっていたら、doctor か hook が警告する。
- hook の逃げ道: 既存のコードの問題で通らない場合に、どう導入をコミットするかを決める（例: 先に整形だけの issue を通す、通らないコマンドを一時的に登録しない）。

## 試した対策（skill-impact.md の行）

- 2026-10-10: 導入のコミット（HEAD に config.ts が無い）に docs/sdd/、.agents/、.gitignore 以外が含まれると hook が中止する。
  sdd-init の手順6で、品質ゲートが通らない原因をコマンドの誤りと既存のコードに分け、既存のコードは直さずに聞くと書いた。
  人役の回答表に「導入では直さない。通るコマンドだけを登録し、残りを直す issue の案を出す」を足した。
  INIT-001 は 0/3 → 3/3。3回とも hook の中止を受けて止まり、既存のコードを直さないと明言して聞いた。
