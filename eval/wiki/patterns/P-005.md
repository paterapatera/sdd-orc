# P-005 sdd-finish で、「OK」を PR の作成の了承とみなし、聞かずに PR を作る

- 状態: 手順で対策（2026-10-10 採用。QUICK-001 0/3 → 3/3）
- 起きた工程: sdd-finish の確認ポイント（開始時の1回）
- 根拠: 20261010-161339-QUICK-001、20261010-162553-QUICK-001、20261010-163632-QUICK-001（3/3 回。composer-2.5、スキル 1a21ed9）

## 何が起きたか

人役は sdd-impl の受け入れテストの依頼に続けて、`OK /sdd-finish` と呼び出した。
AI は3回とも、確認ポイント（受け入れテストの合否、PR を作ってよいか、未コミットの変更の扱い）を聞かずに進め、
`gh pr create` で PR を作った（GitHub の #1〜#3）。1回は issue へのコメントも試みた。人役の回答表では「PR は作らない」。

それまでの6回は `受け入れOK /sdd-finish` と呼び出しており、6回とも PR を作ってよいかを聞いた（人役は断り、作らなかった）。

## なぜ起きたか（推測）

- SKILL.md には「『受け入れOK』だけでは、2と3への回答にならない」と、言い回しそのものを書いている。
  「受け入れOK」はこの文に当たるので聞いたが、ただの「OK」は当たらないと解釈した。
- 同じ時期に gh がログイン済みになった。それまでの回は gh で PR を作れない状態だったので、聞くかどうかに影響した可能性もある。
- 道具で確かめる部分が無い。了承の有無は文章の決まりだけで守らせている。

## 対策の案

- 道具: PR の作成そのものを AI が gh で直接行うので、了承の有無を機械的に確かめる方法が今は無い。
- 手順: 了承とみなす条件を、言い回しの例ではなく機械的に判定できる形で書く
  （例: ユーザーの発言に PR/MR を作ることへの言及が無ければ、必ず聞く）。
- 試験場: 呼び出しの文面を問題の steps に書いて揃える（比べるときに入力がぶれないように）。

## 試した対策（skill-impact.md の行）

- 2026-10-10: sdd-finish の確認ポイントを、回答があるとみなしてよい場合を項目ごとに書く形にした（手順の文章。道具では確かめられないため）。
  QUICK-001 の呼び出しの文面を「OK /sdd-finish」に揃えた。
