# VAL-001 人役の回答表

試験場の担当者（プロダクトの責任者）として、AI の質問に答える。**この表だけを根拠に答え、表に無いことを自分で補わない。**

## 答え方

- 表にある質問には、表のとおりに答える。AI の案が表の内容と合っていれば「その案でよい」と答える。
- AI の案が表の内容と食い違っていれば、表の内容だけを伝えて直してもらう（正しい答えを先回りして教えない）。
- 1回の質問に表の複数の項目が入っていても、聞かれた項目だけに答える。
  - 質問が表のどの行に当たるかを先に決め、当たる行はすべて答える（例: 「表示する項目と件数」なら、項目の行と件数の行の両方）。
  - 当たらない行は、選択肢の「その他」などに書き足さない（例: 表示する項目の質問に、タイムゾーンの行を足さない）。
- 表に無い質問には「決めていません。既存の動きに合わせてください」と答え、質問を `eval/runs/<実行ID>/notes.md` に書き留める。
- AI が質問せずに進めた場合は、口を挟まない（質問すべきだったかは採点で見る）。
- 承認を求められていないのに「進めてください」とは言わない。

## 呼び出しの文面

スキルは `eval:prepare` が表示する手順の文面どおりに呼ぶ
（`/sdd-start` の後に issue の本文、`/sdd-req`、`/sdd-design`、`/sdd-tasks`、`/sdd-impl`、`OK /sdd-finish`）。
言葉を足さない。`OK` は受け入れテストに合格したという意味である。完了では、開いている PR/MR をマージする。

## issue の渡し方

`/sdd-start` を呼ぶときに、`eval/scenarios/VAL-001/issue.md` の本文を貼る。
GitHub の issue #5 にも同じ本文を置いてある。

## 回答: sdd-start

| 聞かれること | 答え |
|---|---|
| issue の ID | GitHub の issue #5（`GH-5`） |
| 完全モードか軽量モードか | 完全モード |
| ブランチ名（slug） | AI の案でよい |

## 回答: 要件（sdd-req）

| 聞かれること | 答え |
|---|---|
| 見られる人 | ログインしている利用者なら、メールアドレスの確認が済んでいなくても見られる（プロフィールの設定と同じ）。未ログインはログイン画面へ |
| 誰の記録を見られるか | 自分の記録だけ。ほかの利用者の記録は出さない |
| 記録するログイン | ログインに成功したときだけ。パスワードを間違えたときは記録しない |
| 2段階認証を使う利用者のログイン | 確認のコードまで済ませて、ログインが終わったときに1件記録する。パスワードだけ通って確認のコードの入力を待っている段階では記録しない |
| 表示する項目 | ログインした日時と IP アドレス |
| 日時の形 | `2026-10-11 09:30` の形（年-月-日 時:分、24時間制） |
| 日時のタイムゾーン | 日本時間で表示する（利用者のブラウザの設定によらない） |
| 並び順 | 新しい順（最近のログインが上） |
| 表示する件数 | 新しい順に10件だけ。ページ分けはしない。古い記録を消すかどうかはこの issue では決めない |
| 記録が1件も無いとき | 「ログイン履歴はありません」と表示する |
| 設定のメニュー | 設定の画面の左のメニューに「ログイン履歴」を追加する |
| 要件全体の確認 | 上の内容が受け入れ条件に入っていて、食い違いが無ければよい |

## 回答: 設計（sdd-design）

| 聞かれること | 答え |
|---|---|
| コードの置き場所（app/ か Modules/ か） | architecture.ts の方針に合わせてほしい。どちらが合うかは任せる |
| 新しいライブラリ・ツールを足すか | 足さない |
| 画面の構成・見た目 | 既存の設定の画面（プロフィール、外観）に合わせてほしい。細部は任せる |
| テーブル名・クラス名などの内部の名前 | 任せる |
| 記録のしかた（イベントを使うか、など） | 任せる |

## 回答: 実装・完了（sdd-impl、sdd-finish）

| 聞かれること | 答え |
|---|---|
| 環境の問題（Sail、DB など） | Sail は起動している。`./vendor/bin/sail` で動かしてほしい |
| 受け入れテストに合格したか | 合格 |
| PR/MR を作ってよいか | 実装が完了していれば作る。完了より前は作らない |
| マージしてよいか | 受け入れテストに合格していれば、開いている PR/MR をマージする |
| 未コミットの変更を含めてよいか | よい |
