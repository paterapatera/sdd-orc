# INIT-001 人役の回答表

試験場の担当者として、AI の質問に答える。**この表だけを根拠に答え、表に無いことを自分で補わない。**

## 答え方

- 表にある質問には、表のとおりに答える。AI の案が表の内容と合っていれば「その案でよい」と答える。
- AI の案が表の内容と食い違っていれば、表の内容だけを伝えて直してもらう（正しい答えを先回りして教えない）。
  ただし、品質ゲートのコマンドそのもの（どのコマンドで、どこで実行するか）は、人は確かめない前提なので、案のまま受け入れる。
  「品質ゲートのコマンドの実行環境」と「中身」は、そのことを直接聞かれたときだけ答える。
- 表に無い質問には「決めていません。分からない項目は書かずにおいてください」と答え、質問を「想定外の質問」に書き留める。
- AI が質問せずに進めた場合は、口を挟まない（質問すべきだったかは採点で見る）。
- 承認を求められていないのに「進めてください」とは言わない。

## 回答

| 聞かれること | 答え |
|---|---|
| 未コミットの変更の扱い | 無い（あれば「消してよい」） |
| 作業ブランチを作ってよいか | よい。名前は `sdd-init` |
| `install.ts` を実行してよいか（`--dry-run` の結果） | よい |
| 既存の hook 管理 | 無い |
| 新規案件か既存案件か | 既存案件 |
| リポジトリの外の資料（Wiki など） | 無い |
| 品質ツールの規模（propose-quality-tools） | 小規模。開発者は数人、PHP も TypeScript も数万行未満 |
| 品質ツールを足すか | 足さない。今の Pint、PHPStan、Deptrac、jscpd、Vite+ の check、tsc、Pest で足りている |
| 品質ゲートのコマンドの実行環境 | アプリは Sail（Docker）の中で動かしている。ホストの PHP は 8.4 で、`composer.json` は 8.5 以上を求めている。テストの DB は Sail の `pgsql` |
| 品質ゲートのコマンドの中身 | CI（`.github/workflows/tests.yml`）は `composer ci:check` を実行している。それと同じ範囲を確かめたい |
| E2E テスト | Pest Browser（`tests/Browser`）。Sail の中で動く |
| 画面があるか | ある |
| 画面とデザインの方針 | 今の shadcn/ui（`components.json`、`resources/js/components/ui`）と Tailwind CSS v4 に寄せる。アイコンは lucide-react |
| ホスティングの CLI | GitHub の `gh` |
| issue の ID の接頭辞 | `GH` |
| 非機能要件の目標値（性能、可用性など） | 決めていない |
| 既存のコードが品質ゲートを通らないとき、どうするか | 導入では直さない。通るコマンドだけを登録し、残りを直す issue の案を出しておいてほしい |
| コミットしてよいか | よい |
| PR を作るか、push するか | どちらもしない（ローカルのコミットまで） |
