# VAL-002 人役の回答表

試験場の担当者（プロダクトの責任者）として、AI の質問に答える。**この表だけを根拠に答え、表に無いことを自分で補わない。**

## 答え方

- 表にある質問には、表のとおりに答える。AI の案が表の内容と合っていれば「その案でよい」と答える。
- AI の案が表の内容と食い違っていれば、表の内容だけを伝えて直してもらう（正しい答えを先回りして教えない）。
- 1回の質問に表の複数の項目が入っていても、聞かれた項目だけに答える。
  - 質問が表のどの行に当たるかを先に決め、当たる行はすべて答える（例: 「表示する項目と利用開始の形」なら、項目の行と利用開始の行の両方）。
  - 当たらない行は、選択肢の「その他」などに書き足さない（例: 表示する項目の質問に、自己紹介の上限の行を足さない）。
- 表に無い質問には「決めていません。既存の動きに合わせてください」と答え、質問を `eval/runs/<実行ID>/notes.md` に書き留める。
- AI が質問せずに進めた場合は、口を挟まない（質問すべきだったかは採点で見る）。
- 承認を求められていないのに「進めてください」とは言わない。

## 呼び出しの文面

スキルは `eval:prepare` が表示する手順の文面どおりに呼ぶ
（`/sdd-start` の後に issue の本文、`/sdd-req`、`/sdd-design`、`/sdd-tasks`、`/sdd-impl`、`OK /sdd-finish`）。
言葉を足さない。`OK` は受け入れテストに合格したという意味である。完了では、開いている PR/MR をマージする。

## issue の渡し方

`/sdd-start` を呼ぶときに、`eval/scenarios/VAL-002/issue.md` の本文を貼る。
GitHub の issue #6 にも同じ本文を置いてある。

## 回答: 要件（sdd-req）

| 聞かれること | 答え |
|---|---|
| メンバーのページを見られる人 | ログインしていて、メールアドレスの確認が済んだ利用者だけ（ダッシュボードと同じ）。未ログインはログイン画面へ、未確認は確認の案内（`/email/verify`）へ |
| 存在しない ID のページ | 404（見つからない）にする |
| メンバーのページに出す項目 | 名前、自己紹介、利用開始の月。メールアドレスは出さない |
| 利用開始の月の形 | `2026年10月から利用` の形（登録した日時の年と月） |
| 利用開始の月のタイムゾーン | 日本時間で数える（例: UTC の 9月30日 16時に登録した人は、10月から利用） |
| 自己紹介の長さ・必須 | 必須ではない（空でよい）。160文字まで |
| 長すぎる自己紹介を保存しようとしたとき | 自己紹介の欄にエラーを出して、保存しない（名前とメールアドレスも保存しない） |
| 自己紹介の改行・HTML | 改行はそのまま改行として表示する。HTML のタグは解釈せず、文字のまま表示する |
| 自己紹介が空のとき | メンバーのページに「自己紹介はまだありません」と表示する |
| `bio` を送らずに名前やメールアドレスを保存したとき | 今の自己紹介は変えない（消さない） |
| 自分のページ | 自分の ID のページも、ほかの人と同じように見られる。特別な表示はしない |
| プロフィールの設定の画面 | 名前、メールアドレスの下に「自己紹介」の入力欄（複数行）を足す |
| 要件全体の確認 | 上の内容が受け入れ条件に入っていて、食い違いが無ければよい |
