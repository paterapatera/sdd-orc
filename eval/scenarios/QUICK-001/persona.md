# QUICK-001 人役の回答表

試験場の担当者として、AI の質問に答える。**この表だけを根拠に答え、表に無いことを自分で補わない。**

## 答え方

- 表にある質問には、表のとおりに答える。AI の案が表の内容と合っていれば「その案でよい」と答える。
- AI の案が表の内容と食い違っていれば、表の内容だけを伝えて直してもらう（正しい答えを先回りして教えない）。
- 表に無い質問には「決めていません。既存の動きに合わせてください」と答え、質問を `eval/runs/<実行ID>/notes.md` に書き留める。
- AI が質問せずに進めた場合は、口を挟まない（質問すべきだったかは採点で見る）。
- 承認を求められていないのに「進めてください」とは言わない。

## issue の渡し方

`/sdd-start` を呼ぶときに、`eval/scenarios/QUICK-001/issue.md` の本文を貼る（例: `/sdd-start` の後に本文を貼り付ける）。
issue は GitHub には無いので、`gh` で取得しようとしたら「GitHub には無い。貼った本文を使ってほしい」と答える。

## 回答

| 聞かれること | 答え |
|---|---|
| issue の ID | GitHub の issue #1（`GH-1`） |
| 完全モードか軽量モードか | 軽量モード |
| ブランチ名（slug） | AI の案でよい |
| architecture.ts に反映されていない構成の変更の扱い | 今回は扱わない |
| メールアドレスを変えたときに、確認メールを自動で送るか | 今回は求めない（今のプロフィール画面の再送で足りる） |
| 大文字と小文字だけを変えた場合 | 変更として扱ってよい（未確認になる） |
| 名前だけを変えた場合（メールアドレスは同じ） | 確認済みのままにする |
| 確認が必要な画面に、未確認で入ろうとしたとき | 今の動きのとおり、確認の案内（`/email/verify`）に回す |
| 期待する動作・受け入れ条件・変えてはいけない振る舞いの確認 | 次の3点が入っていて、食い違いが無ければよい。1. メールアドレスを変えて保存すると未確認になる 2. 未確認の間は、確認が必要な画面に入ると `/email/verify` に回される 3. メールアドレスを変えなければ、確認済みのまま |
| 環境の問題（Sail、DB など） | Sail は起動している。`./vendor/bin/sail` で動かしてほしい |
| 受け入れテストに合格したか（sdd-finish） | 合格 |
| PR/MR を作ってよいか | 作らない。本文の案だけでよい |
| 未コミットの変更を含めてよいか | よい |
