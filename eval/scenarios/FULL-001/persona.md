# FULL-001 人役の回答表

試験場の担当者（プロダクトの責任者）として、AI の質問に答える。**この表だけを根拠に答え、表に無いことを自分で補わない。**

## 答え方

- 表にある質問には、表のとおりに答える。AI の案が表の内容と合っていれば「その案でよい」と答える。
- AI の案が表の内容と食い違っていれば、表の内容だけを伝えて直してもらう（正しい答えを先回りして教えない）。
- 1回の質問に表の複数の項目が入っていても、聞かれた項目だけに答える。
  - 質問が表のどの行に当たるかを先に決め、当たる行はすべて答える（例: 「並び順と件数の扱い」なら、並び順の行と件数の行の両方）。
  - 当たらない行は、選択肢の「その他」などに書き足さない（例: 本文の表示の質問に、長さの上限の行を足さない）。
- 表に無い質問には「決めていません。既存の動きに合わせてください」と答え、質問を `eval/runs/<実行ID>/notes.md` に書き留める。
- AI が質問せずに進めた場合は、口を挟まない（質問すべきだったかは採点で見る）。
- 承認を求められていないのに「進めてください」とは言わない。

## 呼び出しの文面

スキルは `eval:prepare` が表示する手順の文面どおりに呼ぶ
（`/sdd-start` の後に issue の本文、`/sdd-req`、`/sdd-design`、`/sdd-tasks`、`/sdd-impl`、`OK /sdd-finish`）。
言葉を足さない。`OK` は受け入れテストに合格したという意味である。完了では、開いている PR/MR をマージする。

## issue の渡し方

`/sdd-start` を呼ぶときに、`eval/scenarios/FULL-001/issue.md` の本文を貼る。
GitHub の issue #4 にも同じ本文を置いてある。

## 回答: sdd-start

| 聞かれること | 答え |
|---|---|
| issue の ID | GitHub の issue #4（`GH-4`） |
| 完全モードか軽量モードか | 完全モード |
| ブランチ名（slug） | AI の案でよい |

## 回答: 要件（sdd-req）

| 聞かれること | 答え |
|---|---|
| 見られる人 | ダッシュボードと同じ。ログインしていて、メールアドレスの確認が済んだ利用者だけ。未ログインはログイン画面へ、未確認は確認の案内（`/email/verify`）へ |
| 一覧の並び順 | 新しい順（登録した日時の新しいものが上） |
| 一覧に出す項目 | タイトル、本文、登録日（`2026-10-10` の形） |
| 件数が多いとき | 20件ずつのページ分け。2ページ目以降は URL の `?page=2` のように開ける |
| ダッシュボードに出す件数と項目 | 新しい順に3件。タイトルと登録日。一覧の画面へのリンクも置く |
| お知らせが1件も無いとき | 一覧の画面にもダッシュボードにも「お知らせはありません」と表示する |
| 本文の改行・HTML | 改行はそのまま改行として表示する。HTML のタグは解釈せず、文字のまま表示する |
| タイトルと本文の長さ・必須 | どちらも必須。タイトルは100文字まで、本文は2000文字まで |
| 空や長すぎる入力でコマンドを実行したとき | エラーを表示して失敗で終わり（終了コードは0以外）、登録しない |
| 公開日時の予約 | しない。登録した時点で公開する |
| サイドバーのメニュー | 「お知らせ」を追加する |
| 要件全体の確認 | 上の内容が受け入れ条件に入っていて、食い違いが無ければよい |

## 回答: 設計（sdd-design）

| 聞かれること | 答え |
|---|---|
| コードの置き場所（app/ か Modules/ か） | architecture.ts の方針に合わせてほしい。どちらが合うかは任せる |
| 新しいライブラリ・ツールを足すか | 足さない |
| 画面の構成・見た目 | 既存の画面（ダッシュボード、設定）に合わせてほしい。細部は任せる |
| テーブル名・クラス名などの内部の名前 | 任せる |
| 既存の画面の変更（ダッシュボードの置き換えなど） | ダッシュボードの既存の見本の枠（模様の箱）は、お知らせの表示に置き換えてよい |

## 回答: 実装・完了（sdd-impl、sdd-finish）

| 聞かれること | 答え |
|---|---|
| 環境の問題（Sail、DB など） | Sail は起動している。`./vendor/bin/sail` で動かしてほしい |
| 受け入れテストに合格したか | 合格 |
| PR/MR を作ってよいか | 実装が完了していれば作る。完了より前は作らない |
| マージしてよいか | 受け入れテストに合格していれば、開いている PR/MR をマージする |
| 未コミットの変更を含めてよいか | よい |
